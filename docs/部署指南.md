# 部署指南（生产环境）

> 目标：让 **车间里的同事用浏览器打开一个网址就能提问**。
> 本文按"先选路线 → 再改配置 → 再照步骤执行"组织，所有命令可直接复制。

---

## 0. 先看清三个硬约束（决定了可选路线）

| 约束 | 事实（本项目实测） | 影响 |
|---|---|---|
| **模型体积/内存** | bge-m3 6.17GB（运行占 2.2GB 内存）+ 精排 2.14GB（占 2.3GB） | 想用本地模型，服务器**至少 8GB 内存** |
| **显卡** | 本地 4060 Ti 上 embedding 662 条/秒；纯 CPU 约 33.7 条/秒（慢 19 倍） | 云服务器一般没 GPU；GPU 实例 ¥1000+/月，不建议 |
| **国内网络** | `onrender.com` **连接被重置**（实测 Server disconnected）；`huggingface.co` **超时**；Neon(新加坡)、DeepSeek、vercel.com 正常 | **不要**直接把后端放 Render 默认域名；模型必须走国内镜像或提前传上去 |

### 另外两个"必须知道"的性能数字

- **稳态提问**：CPU 部署约 **10~15 秒**（本地 GPU 是 7.5 秒）——完全可以接受
- **导入资料**：约 **1.2 秒/块**（瓶颈是 HyPE 每块一次 LLM 调用），100 块≈2 分钟、500 块≈10 分钟

## 1. 三条路线，选一条

| | **A. 国内云 + Docker（推荐）** | **B. Render（最快，但要绕域名）** | **C. 本机 + 隧道（零成本试跑）** |
|---|---|---|---|
| 后端放哪 | 阿里云/腾讯云轻量 4C8G | Render（Docker，`render.yaml` 已备好） | 你现在这台电脑 |
| 检索质量 | ★★★ 本地模型 + 精排 | ★★ 需用 API 嵌入 + 关精排（省内存） | ★★★ 本地 GPU，最快 |
| 国内可访问 | ✅ 直连 | ⚠️ `onrender.com` 被重置，**必须绑自定义域名** | ✅（Cloudflare 隧道） |
| 成本 | 约 ¥60~120/月 | 免费档内存不够；Standard 约 $7~25/月 | ¥0 |
| 数据库 | 容器内 pgvector（延迟 ~1ms） | Neon（跨境每次 SQL ~0.3s） | Neon（同左） |
| 工期 | 1~2 小时（含传模型） | 30 分钟 | 15 分钟 |
| 适合 | **正式给同事用** | 快速验证/临时演示 | 内部试跑、给小范围人看 |

**建议**：正式用选 **A**；只想先给几个人看，用 **C** 最快；**B 只在你愿意加自定义域名时选**。

## 2. 动手前必须改的 5 项（不改就用不了）

| # | 配置 | 现在 | 必须改成 | 不改的后果 |
|---|---|---|---|---|
| 1 | `ADMIN_TOKEN` | `change-me` 或占位中文 | 随机串：`python -c "import secrets;print(secrets.token_urlsafe(32))"` | 管理接口不可用；若保留默认值等于公开 |
| 2 | `CORS_ORIGINS` | `http://localhost:3000,...` | 你的前端真实域名（https，无结尾斜杠） | 前端所有请求被浏览器拦截 |
| 3 | 前端 `NEXT_PUBLIC_API_BASE` | 未设置 | 后端公网地址（`https://api.你的域名`） | 前端会去请求 localhost，线上全挂 |
| 4 | `DEEPSEEK_API_KEY` | 本地那份 | 生产用独立 key（便于限额/审计） | 无法生成答案 |
| 5 | `ENVIRONMENT=prod` + `DEBUG=false` | dev/true | prod/false | 会把堆栈信息暴露给浏览器 |

## 3. 方案 A：国内云 + Docker Compose（推荐）

### A1. 买服务器

| 项 | 建议 |
|---|---|
| 规格 | **4 核 8GB**（2 核 4GB 只能跑"关闭精排 + API 嵌入"的省内存档） |
| 系统 | Ubuntu 22.04 / 24.04 LTS |
| 磁盘 | 系统盘 40GB+（代码 + 模型 8.3GB + 上传件） |
| 带宽 | 3M 起；建议 5M（上传大 PDF 才不难受） |
| 区域 | 尽量靠近使用者；**如果坚持用 Neon，就选新加坡/香港**（同区域省跨境延迟） |

### A2. 装 Docker

```bash
# 服务器上执行
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker    # 免 sudo
docker --version && docker compose version
```

### A3. 把代码传上去

```bash
# 服务器
sudo mkdir -p /opt/fsrag && sudo chown $USER /opt/fsrag
git clone <你的仓库地址> /opt/fsrag        # 或者用 scp/rsync 传压缩包
cd /opt/fsrag
```

> ⚠️ 仓库里不要有 `.env.prod`、`data/`（模型和在库文档都不该进 git）。`.gitignore` 已包含。

### A4. 准备模型（三选一，**建议 ①**）

| 方式 | 做法 | 优缺点 |
|---|---|---|
| **① 从开发机传上去** | 见下方命令 | 最快最稳，一次性 8.3GB |
| ② 服务器上从镜像站下载 | `export HF_ENDPOINT=https://hf-mirror.com` 后让程序首次加载时下载 | 不用传，但首次提问会卡很久、且依赖镜像站 |
| ③ 不用本地模型 | `.env.prod` 里 `EMBEDDING_PROVIDER=siliconflow` + `RERANK_PROVIDER=none` | 省 4.5GB 内存，2C4G 就够；质量略降、需 SiliconFlow key |

**方式 ① 的命令**（在你 Windows 开发机上执行）：

```powershell
cd D:\xiaofangRAG\fire-safety-rag
# 打包（约 8.3GB → 压缩后 2.5~3.5GB，取决于格式）
tar -czf hf_cache.tar.gz -C backend\data\indexes hf_cache
# 上传（把 root@IP 换成你的服务器）
scp hf_cache.tar.gz root@你的服务器IP:/opt/
```

```bash
# 服务器上解压到挂载点
cd /opt/fsrag
mkdir -p backend/data/indexes
tar -xzf /opt/hf_cache.tar.gz -C backend/data/indexes
du -sh backend/data/indexes/hf_cache      # 应看到 ~8.3G
```

### A5. 写配置文件

```bash
cd /opt/fsrag
cp deploy/.env.prod.example .env.prod
python3 -c "import secrets;print(secrets.token_urlsafe(32))"   # 生成 ADMIN_TOKEN
nano .env.prod        # 填 DEEPSEEK_API_KEY / ADMIN_TOKEN / CORS_ORIGINS
```

还需要在仓库根目录建一个 `.env` 给 compose 读数据库密码：

```bash
cat > .env <<'EOF'
POSTGRES_PASSWORD=换成你的强密码
EOF
chmod 600 .env .env.prod
```

### A6. 起服务

```bash
cd /opt/fsrag
docker compose up -d --build          # 首次 10~20 分钟（装依赖）
docker compose ps                     # 三个容器都应 healthy / running
docker compose logs -f api            # 观察启动日志，Ctrl+C 退出查看
curl -s localhost:8000/health         # 期望 {"status":"ok","database":true,...}
```

> 第一次 `/health` 可能要等 **60~120 秒**（模型加载进内存），`start_period` 已设 120s。

### A7. 绑定域名 + HTTPS

```bash
# 1) DNS：把 api.你的域名 的 A 记录指向服务器公网 IP
# 2) 先拿证书（nginx 已配好 /var/www/certbot 校验目录）
cd /opt/fsrag
mkdir -p deploy/certs
docker run --rm -v $PWD/deploy/certs:/etc/letsencrypt \
  -v fsrag_certbot-www:/var/www/certbot \
  certbot/certbot certonly --webroot -w /var/www/certbot \
  -d api.你的域名 --email 你的邮箱 --agree-tos --no-eff-email

# 3) 把证书软链到 nginx 读取的目录，并启用 443 配置
cp deploy/certs/live/api.你的域名/fullchain.pem deploy/certs/fullchain.pem
cp deploy/certs/live/api.你的域名/privkey.pem   deploy/certs/privkey.pem
# 4) 按 deploy/nginx.conf 末尾注释，放开 443 的 server 块，把 server_name 改成你的域名
nano deploy/nginx.conf
docker compose restart web
curl -I https://api.你的域名/health
```

> **为什么一定要 HTTPS**：浏览器的剪贴板 API（我们的"复制答案/复制出处"）只在 https 或 localhost 下可用。

### A8. 前端部署（Vercel）

1. Vercel → New Project → 选仓库
2. **Root Directory = `frontend`**（关键，否则找不到 Next 配置）
3. Environment Variables：
   ```
   NEXT_PUBLIC_API_BASE = https://api.你的域名
   ```
   （这是**构建时注入**的，改了必须 Redeploy）
4. Deploy 完成后，把 Vercel 给的域名加到服务器 `.env.prod` 的 `CORS_ORIGINS`，然后
   ```bash
   docker compose up -d api      # 让新的 CORS 生效
   ```

### A9. 导入资料

```bash
# 方式一：界面上传（推荐，导入即在同一进程内生效）
# 方式二：命令行
docker compose exec api python scripts/ingest_cli.py \
  --file /app/data/uploads/xxx.pdf --category law
# ⚠️ 命令行导入后必须重启 api，否则 BM25 语料是旧的
docker compose restart api
```

### A10. 验收清单（逐条打勾）

- [ ] `curl https://api.你的域名/health` 返回 `status=ok, database=true, llm_configured=true`
- [ ] 浏览器打开前端域名，顶栏显示"服务正常"
- [ ] 问一个问题，**首次**等 60~120 秒后拿到带 `[1]` 引用的答案
- [ ] 再问一次，**约 10~15 秒**返回（稳态）
- [ ] 答案里的 `[1]` 可点 → 右侧出处面板高亮
- [ ] "复制答案"可用（验证 HTTPS 生效）
- [ ] 上传一个 PDF → 状态走到"已完成"，块数合理，能"查看切块"
- [ ] 问一个库外问题 → 琥珀色"资料中未收录"（不是编造）
- [ ] `docker compose ps` 三个容器都是 healthy

## 4. 方案 B：Render（最快，但国内需绕域名）

仓库里 `render.yaml` 已备好（**免费档 + API 嵌入 + 关精排**），但注意：

1. **免费档只有 512MB 内存**，装不下本地模型 → 必须 `EMBEDDING_PROVIDER=siliconflow`（要有 SiliconFlow key）+ `RERANK_PROVIDER=none`
2. **`onrender.com` 在国内被重置**（本次实测 `Server disconnected`）→ 必须绑自定义域名：
   - Render Dashboard → Settings → Custom Domain 加 `api.你的域名`
   - DNS 用 Cloudflare（橙色云开启）代理到 Render
   - 这样访问的是你的域名，绕开 onrender.com
3. 数据库直接用现有 Neon（`sync: false` 的面板手填 `-pooler` 串）
4. 内存建议：至少 **Standard (2GB)**，否则 torch + OCR 依赖容易 OOM

**操作**：Render → New → Blueprint → 选仓库 → 填 4 个 secret（DEEPSEEK_API_KEY / DATABASE_URL / SILICONFLOW_API_KEY / REDIS_URL 可留空）→ 部署 → 绑域名 → 前端 `NEXT_PUBLIC_API_BASE` 指向自定义域名。

## 5. 方案 C：本机 + 隧道（零成本试跑，15 分钟）

适合"先给 3~5 个人看"，**速度最快**（本机 GPU）。

```powershell
# 1) 起后端（本机）
cd D:\xiaofangRAG\fire-safety-rag\backend
$env:PYTHONPATH = 'D:\xiaofangRAG\fire-safety-rag\backend'
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 2) 装 cloudflared 并开隧道（另开一个窗口）
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://127.0.0.1:8000
# 记下它给你的 https://xxxx.trycloudflare.com
```

```powershell
# 3) 前端：把该地址写进环境变量后重启
cd D:\xiaofangRAG\fire-safety-rag\frontend
"NEXT_PUBLIC_API_BASE=https://xxxx.trycloudflare.com" | Set-Content .env.local
# 停掉 npm run dev 再重新起（NEXT_PUBLIC_* 是构建时注入）
npm run dev
```

⚠️ 隧道地址是**临时的**（每次重启都变），且**你的电脑必须一直开着**。要稳定就升级到命名隧道（需 Cloudflare 账号 + 域名）。

## 6. 上线后运维

| 事项 | 命令/做法 |
|---|---|
| 看日志 | `docker compose logs -f api --tail=200` |
| 重启后端 | `docker compose restart api`（改 `.env.prod` 后必须） |
| 更新代码 | `git pull && docker compose up -d --build api` |
| 备份数据库 | `docker compose exec db pg_dump -U fsrag fsrag > backup_$(date +%F).sql` |
| 备份上传件 | `docker run --rm -v fsrag_uploads:/d -v $PWD:/b alpine tar czf /b/uploads.tar.gz -C /d .` |
| 磁盘告警 | `df -h`（模型 8.3G + 上传件会持续增长） |
| 查内存 | `docker stats --no-stream`（本地模型档常驻 ~3~4G） |
| 回滚 | `git checkout <上一个commit> && docker compose up -d --build api` |

**备份策略建议**：数据库每天 pg_dump 到对象存储；`data/uploads` 每周一次；`.env.prod` 单独抄一份离线（丢了要重配）。

## 7. 常见故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器报 CORS 错误 | `CORS_ORIGINS` 没加前端域名 / 带了结尾斜杠 | 改 `.env.prod` → `docker compose up -d api` |
| 前端所有请求打 localhost | 忘了设 `NEXT_PUBLIC_API_BASE`，或设了没 Redeploy | Vercel 改环境变量后 **Redeploy** |
| 502 Bad Gateway | api 容器还没起好（模型在加载） | 等 2 分钟；`docker compose logs api` 看是否 OOM |
| 上传报 413 | nginx 没放开体积 | `client_max_body_size 50m`（`deploy/nginx.conf` 已含） |
| 首次提问超时/504 | 模型加载 60~120 秒，超过反向代理超时 | `proxy_read_timeout 600s`（已含）；或先把模型加载预热 |
| 导入后问不到新资料 | 用**命令行**导入，运行中的进程缓存是旧的 | `docker compose restart api`（界面导入无需重启） |
| 导入 500 / `No space left` | 磁盘满（模型 + 上传件） | `df -h`，清理旧上传件或扩容 |
| 内存 OOM 反复重启 | 8GB 机器同时加载 bge-m3 + 精排 | 换 `RERANK_PROVIDER=none`（省 2.3GB），或升 16GB |
| 中文乱码/答非所问 | 扫描件 OCR 质量差，或 PDF 是双栏未正确处理 | 看"查看切块"内容；乱码 PDF 先用 MinerU 转 Markdown 再导入 |
| 模型下载卡住 | huggingface.co 被墙 | 服务器上 `export HF_ENDPOINT=https://hf-mirror.com` 或用 A4 方式① 直接传 |

## 8. 附：不用 Docker 的话（systemd）

```ini
# /etc/systemd/system/fsrag-api.service
[Unit]
Description=fire-safety-rag api
After=network.target postgresql.service

[Service]
Type=simple
User=fsrag
WorkingDirectory=/opt/fsrag/backend
Environment="PYTHONPATH=/opt/fsrag/backend"
EnvironmentFile=/opt/fsrag/.env.prod
ExecStart=/opt/fsrag/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now fsrag-api
sudo systemctl status fsrag-api && journalctl -u fsrag-api -f
```

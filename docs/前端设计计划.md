## 0. 先回答：能借鉴 Meta 的主页吗

**能借鉴它的"工艺"，不能照搬它的"内容模式"。**

`meta.com` 主页是**营销站**，它做得好的是视觉工艺：

| 可借鉴 | 具体做法 |
|---|---|
| 字号阶梯的**果断** | 一个页面里只有 2~3 个字号级别，且相差足够大（如 56/20/14），不做 16/17/18 这种黏糊的过渡 |
| 留白的**节奏** | 区块之间用大间距（64~96px）分隔，靠空间而非分割线划分区域 |
| 颜色的**克制** | 整页只有 1 个强调色 + 中性灰阶，强调色只出现在"可操作"元素上 |
| 真实内容做视觉主体 | 用真实产品截图/数据，而不是抽象插画或图标拼贴 |

**不能照搬的**：营销 hero（大标题 + 一张图 + 一个 CTA）、渐变背景、轮播、装饰性动效。
这是给**车间安全员**在生产环境用查规范的工具，用户的目标是"3 秒内拿到哪本规范哪一条哪个数值"，
任何不承载信息的视觉元素都是干扰。

**更该学的三个对象**：

| 参考 | 学什么 | 对应到本项目 |
|---|---|---|
| **Perplexity** | **答案 + 可点引用 + 来源卡片的并列关系**（这是本项目最核心的界面语言） | 答案里的 `[1]` 可点 → 右侧出处面板高亮该段原文 |
| **Linear** | 设计语言一致性、键盘优先、极简 chrome | `/` 聚焦输入、`Esc` 关面板、无多余按钮 |
| **Stripe Docs** | 长文与代码块的可读性、层级 | 规范条文、Markdown 表格的排版 |

## 1. 现状诊断（基于代码实测）

| 现状 | 实测数据 | 问题 | 对用户的影响 |
|---|---|---|---|
| 答案渲染 | `AnswerBody` 只按换行 + 项目符号切段 | **不渲染 Markdown**：表格、加粗、多级列表全部显示原文 | 数值类答案（GB 51283 防火间距表）会变成一堆 `\| --- \|`，**看不懂** |
| 引用 | `Rich` 把 `[n]` 渲染成静态 `<span>` | **引用不可点、与出处无关联** | 用户要自己数"第几个出处"，核对成本高 |
| 出处 | `<details>` **默认折叠** | 与"citation-first"相反 | 用户常直接跳过出处，信任度降低 |
| 等待过程 | 有计时器 + 12 秒后的提示 | **无阶段反馈**（稳态 7.5 秒纯干等） | 体感比实际更慢 |
| 导航 | 4 个平级 tab | 主任务（问答）与支撑面（资料库/设置）**无层级** | 移动端要挤 4 个按钮；新用户不知道先做什么 |
| 拒答 | 与正常答案同样式 | "资料中未找到"看起来像普通回答 | 用户误以为库里有这条 |
| 移动端 | 仅 1 个 `@media (max-width:720px)` | 单断点，平板（768~1024）无适配 | 车间用平板时布局挤压 |
| 深色模式 | 无 | 夜班/车间弱光环境刺眼 | 亮度不适 |
| 资料覆盖 | 顶栏无提示 | 用户不知道该问什么 | 提问超出资料范围 → 频繁拒答，体验受挫 |

## 2. 设计原则（5 条，每条都对应到取舍）

1. **答案与出处同位（citation-first）**
   引用条**常驻**在答案下方而非折叠；`[n]` 可点、hover 预览、点击定位。
   *取舍*：多占约 40px 高度，但把"核对原文"从 3 步降到 1 步——消防场景这一条最重要。

2. **慢要慢得透明**
   把等待拆成可读阶段（检索→比对→组织），并明确"首次需加载模型 60~90 秒"。
   *取舍*：不假装快；宁可文案诚实，也不上假进度条。

3. **安全语汇与错误语汇分开**
   - 拒答（资料中没有）= **琥珀色"未收录"**，不是红色错误
   - 强制条文、数值 = 强调样式（浅红底 + 左边框）
   - 真正的错误（网络/500）= 红色 + 重试按钮
   *取舍*：多一套语义色，但能避免"系统坏了"的误判。

4. **零学习成本：4 个任务，不是 4 个模块**
   主屏只做一件事（提问）。资料库/会话/设置退到二级入口。
   *取舍*：主导航变少，但需要一次性的认知迁移。

5. **视觉克制：1 个强调色 + 灰阶**
   **青绿作交互色**（与暖调背景形成冷暖对比，且不与"警示橙"混淆），
   **暖色只留给语义**：红=警示/强制条文，琥珀=拒答/未收录，**不做主色**。
   *取舍*：不做"消防感"的视觉包装（红色大标题），换来长时间使用的舒适度。

## 3. 信息架构改造

**现状**：`问答 | 会话 | 资料库 | 设置` 四个平级 tab。

**目标**：

```
┌─ 顶栏 ─────────────────────────────────────────────┐
│ 🧯 工厂消防问答   [📚 3 份资料 · 527 块 ▾]   ● 正常  ⚙ │
└────────────────────────────────────────────────────┘
        │                    │                │
        │                    │                └─ 设置：右侧抽屉（440px 滑入）
        │                    └─ 资料库：全屏二级页（左上返回）
        └─ 会话：左侧抽屉（320px 滑入，含"新建会话"）

主屏（默认）= 问答，占满剩余空间
```

| 变化 | 理由 |
|---|---|
| 4 tab → 1 主任务 + 3 入口 | 用户 90% 时间在问答；抽屉在移动端天然可用 |
| 顶栏加"资料覆盖"徽标（3 份 · 527 块） | 让用户**知道库的边界**，减少超范围提问；点击直接进资料库 |
| 会话改左侧抽屉 | 会话是"切换上下文"，属辅助动作，不该占一个主 tab |
| 设置改右侧抽屉 | 低频操作，不需要整页 |

## 4. 逐屏规格

### 4.1 问答主屏（核心，占 80% 工作量）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏                                                          │
├───────────────────────────────────────────┬──────────────────┤
│  对话流（居中，最大宽度 760px）            │  出处面板（可选） │
│                                            │  420px，默认关   │
│  ┌──────────────────────┐（右，浅蓝）      │  ┌────────────┐  │
│  │ 我们厂甲B类鹤管到厂房 │                  │  │ [1] GB51283 │  │
│  │ 防火间距至少多少米？  │                  │  │ 4.1.5 表    │  │
│  └──────────────────────┘                  │  │ …原文…      │  │
│                                            │  │ ← 高亮命中段 │  │
│  ┌ 答案卡（左，白卡，圆角 14） ┐             │  └────────────┘  │
│  │ 【结论】30m                 │             │                  │
│  │ 【依据】…[1]  …[2]          │             │                  │
│  │ 【操作要点】                 │             │                  │
│  │  1. …                       │             │                  │
│  │  ┌ 表格（Markdown 渲染） ┐   │             │                  │
│  │  │ 相邻工厂 │ 27 │ 30 │   │   │             │                  │
│  │  └───────────────────────┘   │             │                  │
│  └─────────────────────────────┘             │                  │
│  引用条（常驻）：[1]《GB 51283》4.1.5  [2]《消防法》第十九条      │
│  元信息：7.5s · 语义缓存命中 · deepseek-chat · 复制             │
│                                            │                  │
├───────────────────────────────────────────┴──────────────────┤
│  输入区：[ 提问…                              ]  [发送]        │
│  提示：Enter 发送 · Shift+Enter 换行 · / 聚焦 · ↑ 调出上一问    │
└──────────────────────────────────────────────────────────────┘
```

**答案卡的结构化渲染**（替代现有的纯文本切段）：

| 段落 | 识别 | 呈现 |
|---|---|---|
| 结论 | `结论：` 开头 | 16px 加粗，浅灰底小卡 |
| 依据 | `依据：` 开头 | 正文 + 行内可点引用徽标 `[n]` |
| 操作要点 | `操作要点：` 开头 | 有序列表，行距 1.7 |
| 表格 | 连续 `\| … \|` 行 | 真 `<table>`，表头浅灰、数值右对齐、横向可滚动 |
| 加粗 / 行内代码 | `**x**` / `` `x` `` | 对应样式 |

**等待状态机**（文案分级，非精确进度）：

| 已用时间 | 文案 | 附加 |
|---|---|---|
| 0~1s | 正在检索资料… | 不确定进度条 |
| 1~3s | 正在比对条款… | — |
| 3s+ | 正在组织回答…（12s） | — |
| >12s 且首次 | 首次提问需加载模型 60~90 秒，请稍候 | 说明条 |

**引用联动**（本计划最关键的一处交互）：
- 点 `[1]` → 右侧出处面板滑出，滚动到第 1 条并**高亮**（600ms 淡出）
- hover `[1]` → 浮层预览"《GB 51283》4.1.5 · 第14页"（不做全文预览，避免遮挡）
- 出处面板内每条有"复制原文"、相关度分数、命中片段高亮
- `Esc` 关闭面板

**空态**：保留现有 4 条建议问题，但改为**按资料分组**（如"GB 51283 数值类 / 消防法责任类"），
并显示"当前资料：3 份 · 527 块"。

**错误态**：红色边框 + 原因 + 「重试」按钮（重发同一问题）。

### 4.2 出处面板
- 宽度 420px，可拖拽（最小 320 / 最大 560）
- 每条：序号徽标 + 文档名 + 章节 + 页 + 相关度（≥0 蓝、<0 灰）+ 原文（等宽字体 13px/1.7）
- **命中片段高亮**：用答案里引用的关键句在原文中做粗匹配，命中处浅黄底
- 底部："复制全部出处"（Markdown 格式）

### 4.3 会话抽屉（左）
- 列表项：首问摘要（2 行截断）+ 时间 + 轮数 + 删除
- 顶部"＋ 新建会话"
- 当前会话高亮左边框

### 4.4 资料库（二级页）
- 上传区：拖拽 + 点击，显示进度条（已有 XHR 进度）
- 文档表：标题 / 分类 / 块数 / 状态（**状态色带**：indexed 绿 / 处理中 蓝脉冲 / failed 红）/ 操作
- 行展开 → 切块列表（分页，等宽字体，显示 HyPE 假想问题是否生成）
- 顶部统计："3 份 · 527 块 · 上次导入 10-16 11:15"

### 4.5 设置（右侧抽屉）
分组：检索（top_k、缓存、改写、资料范围）/ 外观（主题、字号）/ 服务（API 地址、健康、统计）/ 管理口令
每项**带一行说明**（现在很多项只有名字，用户不知道为什么开）。

### 4.6 全局
- 顶栏健康点：绿=正常 / 黄=数据库通但 LLM 未配 / 红=后端不可达；hover 显示详情
- toast：右侧上方堆叠，3 种语义色，5s 自动消失，可手动关
- 骨架屏：历史加载、文档列表加载用骨架而非"正在加载…"

## 5. 视觉系统（token 级，可直接落地）

**色板（Glass v2 · 暖调玻璃）**

> 设计取舍：**背景是"实图"**（消防救援散景照，浅色主题用提亮去饱和版、深色用原图），
> **毛玻璃只做在控件上**（输入框、按钮、徽标、卡片、抽屉）——不做在背景上，
> 否则背景会被糊成一片、既看不到图也没有层次。

| 用途 | Token | 亮色（暖纸玻璃） | 深色（余烬玻璃） |
|---|---|---|---|
| 页面底色 | `--bg` | `#efe9e1` | `#0c0e13` |
| 玻璃面 | `--glass` | `rgba(255,255,255,.66)` | `rgba(255,255,255,.085)` |
| 重玻璃（顶栏/输入框/抽屉） | `--glass-strong` | `rgba(253,250,246,.88)` | `rgba(16,18,23,.86)` |
| 玻璃描边 | `--glass-border` | `rgba(74,52,32,.16)` | `rgba(255,255,255,.16)` |
| 顶部内高光 | `--glass-highlight` | `rgba(255,255,255,.95)` | `rgba(255,255,255,.12)` |
| 主文本 | `--ink` | `#201a15` | `#ece7e1` |
| 次文本 | `--ink-2` | `#5c5147` | `#b5aba2` |
| 弱文本 | `--ink-3` | `#8f8479` | `#7e746b` |
| 分割线 | `--line` | `rgba(74,52,32,.14)` | `rgba(255,255,255,.13)` |
| **交互色（青绿）** | `--brand` | `#0f8a7e` | `#2dd4bf` |
| 交互色浅底 | `--brand-soft` | `rgba(15,138,126,.12)` | `rgba(45,212,191,.14)` |
| **警示/强制条文** | `--warn` | `#b23a2c` | `#f87171` |
| **拒答/未收录** | `--amber` | `#a86a12` | `#e0a83c` |
| 成功 | `--ok` | `#2f7d4f` | `#34d399` |

**玻璃实现要点**（缺一不可，否则看着像半透明色块而不像玻璃）：
1. `backdrop-filter: blur(18~24px) saturate(1.4~1.7)` —— 模糊 + 提饱和；
2. `1px` 半透明描边（`--glass-border`）+ `inset 0 1px 0` 顶部内高光；
3. 大而柔的外阴影（负 Y 偏移），让控件"浮"在背景上；
4. 输入框额外加一条**顶部高光弧**（`.composer-inner::before`）。

**背景层结构**：`实图 → 薄纱（上 0.42 / 中 0.22 / 下 0.5 的暖白或暗罩）→ 冷暖辉光 + 四角暗角`，
三层叠加保证"图看得清、字读得清"。顶栏 `▧` 可一键关掉背景图。


**字号阶梯**（只有 6 级）

| 层级 | 字号/行高 | 用途 |
|---|---|---|
| Display | 32/1.2 | 空态主标题 |
| H2 | 20/1.35 | 区块标题 |
| Body | 15/1.75 | 答案正文（**中文行高必须 ≥1.7**） |
| UI | 14/1.5 | 按钮、表单 |
| Small | 13/1.6 | 出处原文、元信息 |
| Micro | 12/1.4 | 徽标、时间 |

**间距**：4pt 基准 → `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`
**圆角**：`6`（控件）· `10`（卡片）· `999`（胶囊）
**阴影**：3 级（沿用现有 `--shadow-sm/md/lg`）
**字体**：系统栈，**不引入 Web Font**（工厂内网可能无外网，字体加载会拖慢首屏）
```css
font-family: -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif;
```
**动效**：只允许 3 处
| 场景 | 时长 | 缓动 |
|---|---|---|
| 消息进入 | 180ms | ease-out（位移 6px + 淡入） |
| 抽屉/面板 | 220ms | cubic-bezier(.2,.8,.2,1) |
| 引用高亮 | 600ms | 淡出 |

`@media (prefers-reduced-motion: reduce)` 下全部关闭。

**断点**（补到 3 个）：`<640` 手机（面板改全屏）· `640~1024` 平板（双栏收成单栏）· `>1024` 桌面（双栏）

## 7. 技术方案与取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| UI 组件库（Ant/MUI/shadcn） | **不引入** | 现有 333 行纯 CSS 已有完整 token 体系；引入组件库与它冲突，且体积增加 100KB+（工厂内网带宽有限） |
| Markdown 渲染 | **自写 `renderAnswer()`（约 100 行）** | 模型输出受 prompt 约束，是**可控子集**（三段式/表格/加粗/列表/引用）。引入 react-markdown 需 3 个依赖，且要额外处理 XSS |
| 表格 | 检测连续 `\|` 行 → `<table>` | 纯正则，无依赖 |
| 引用联动 | `[n]` 点击 → 面板滚动 + `scrollIntoView` + 临时 class | 无需状态库 |
| 状态管理 | 继续用 `useState`，新增 1 个 `UIProvider`（主题/面板开合） | 规模不需要 Redux/Zustand |
| 流式输出 | **P3 再做**（需后端 SSE，本轮不动后端） | 前后端耦合改动，风险高 |
| 深色模式 | P3，CSS 变量 + `data-theme` | 现在是硬编码变量，改造成本低但需逐屏校对 |
| 性能预算 | 首屏 JS ≤ 120KB（gzip），无 Web Font，无图片资源 | 内网环境 |

## 10. 明确不做（范围控制）

1. 不做营销式 hero / 大图 / 轮播 / 渐变装饰
2. 不做"消防感"的红色主题包装（红色只表警示）
3. 不引入 UI 组件库、图标库（图标用少量内联 SVG）
4. 不改后端接口（P0~P2），除 P3 的 SSE
5. 不做多语言、不做暗色以外的主题
6. 不加图表/仪表盘（当前没有需要可视化的时序数据）

## 11. 风险与回退

| 风险 | 影响 | 回退 |
|---|---|---|
| 改导航结构（P1）破坏使用习惯 | 中 | P1 前先备份 `page.js`；导航与视觉可分开提交，出问题只回退导航 |

| 素材/字体不可用 | 低 | 全系统字体 + 内联 SVG，无外部资源 |

# 项目导览（读代码用）

> 面向"准备通读代码"的人。**先看这份，再按 §2 的路径深入**，比从 `main.py` 一路读到底快得多。

---

## 0. 一分钟看懂

**做什么**：工厂消防知识问答助手。员工用口语提问，系统在规范原文里检索出条款，用 DeepSeek 生成
带 `[n]` 引用的答案；资料里没有的**必须拒答**（消防场景不容编造）。

**知识库现状**：3 份资料 / **527 块**（GB 51283 标准 346 · 消防法 122 · GB/T 38315 导则 59），
全部带 HyPE 假想问题。

**技术栈**：FastAPI + LlamaIndex + DeepSeek(deepseek-chat) + BAAI/bge-m3 + bge-reranker-v2-m3 +
PostgreSQL/pgvector（线上 Neon 新加坡）+ Next.js 14。GPU：RTX 4060 Ti 8GB（embedding 与精排都在 GPU）。

**评估基线**（140 条人工校对题目）：

| 层 | 指标 | 实测 | 门槛 |
|---|---|---|---|
| 检索 | HitRate@10 / MRR@10 | 1.000 / **0.949** | ≥0.85 / ≥0.70 ✅ |
| 检索 | 跨文档串味 | **0%** | ≥0.80 ✅ |
| 生成 | context_precision / recall | 0.936 / 0.963 | ≥0.75 ✅ |
| 生成 | **faithfulness** | **0.832** | **≥0.90 ❌ 未达标** |
| 安全 | 拒答正确率（7 条负样本） | **100%** | ≥0.90 ✅ |

> ⚠️ 检索指标存在**循环性虚高**（题目由切块自动生成，与原文措辞高度重叠），
> 详见 `docs/评估方案.md` §2 的"如何正确解读这组数字"。

## 3. 核心文件说明（职责 · 关键函数 · 为什么这么写）

### 入口与配置

| 文件 | 职责 | 关键点 |
|---|---|---|
| `app/main.py` | FastAPI 装配、CORS、异常处理、启动事件 | 全部路由处理器用**同步 `def`**（走线程池），因为 LlamaIndex 链路是同步的，混用 async 会报 `Detected nested async` |
| `app/config.py` | 所有配置项与开关 | `apply_hf_cache_env()` 保证缓存目录**永不为空**（HF 缓存目录不可写会导致加载失败）；`model_cache_dir` **刻意不叫 `hf_home`**，避免与环境变量名冲突 |
| `app/dependencies.py` | 模型**单例** | 全部用 `lru_cache`。曾经的性能事故：`utils/cache.py` 里误用 `build_embed_model()` 导致每次问答把 2.2GB 的 bge-m3 加载两遍（50 秒/问） |

### 入库链路（`app/core/ingestion/`）

| 文件 | 职责 | 关键点 |
|---|---|---|
| `loader.py` ⭐ | PDF/DOCX/HTML/TXT → 文本 | ① **三阶梯解析**：pdfplumber → 质量分判定 → PyMuPDF → OCR；② **双栏按栏提取**（`_looks_two_column` 用"词块中心点落在中轴带的比例"判定，投影法实测区分不出来）；③ **表格转 Markdown** 并用 `outside_bbox` 从正文剔除；④ `normalize_width()` 全角→半角 + 清数字周围空格；⑤ 技术图只打标记不假装识别 |
| `quality.py` | 文本质量分（判断乱码/扫描件） | 判据是**常用字覆盖率**：正常中文约 0.325，方正书版乱码 ≤0.0013；`(cid:` 标记是决定性乱码信号 |
| `ocr.py` | PaddleOCR 兜底 | 自动适配 2.x/3.x API 差异；逐页磁盘缓存 |
| `chunker.py` ⭐ | 切块 | ① `split_by_heading()` 按标题切段（**数字编号后的空格必须是可选 `\s*`**，否则归一化后标题全失效）；② `is_low_value_chunk()` 丢弃目次/封面/前言/参考文献（**段落级与切块级都要过滤**）；③ `SemanticSplitterNodeParser` 用 embedding 找语义断点，标题链拼进正文让向量"看见"章节 |
| `hyphe.py` | 为每块生成 3 个口语化假想问题 | 参与 embedding、不参与展示。没有 LLM 时会**静默跳过**（曾经 Web 上传因此丢功能） |
| `embedder.py` | bge-m3 加载 | `find_cached_model_path()` 找**本地完整快照**——国内访问不了 huggingface.co，必须绕开 Hub 查询；`resolve_device()` 自动选 cuda 并按显存调 batch |
| `indexer.py` | 入库总编排 | `--force` 删除旧文档时**必须同时删向量**；用 `NodeRelationship.SOURCE` 关联文档（用 metadata 会被 `node_to_metadata_dict` 覆盖成 `ref_doc_id`） |

### 检索链路（`app/core/retrieval/`）

| 文件 | 职责 | 关键点 |
|---|---|---|
| `hybrid.py` ⭐ | 稠密(pgvector) + 稀疏(BM25) 双路 | `_RETRIEVER_CACHE` 按 `(use_rerank, top_k, doc_category)` 缓存；BM25 语料用**原生 SQL** 从 `chunks` 表加载（走 LlamaIndex 取不到） |
| `fusion.py` | RRF 融合 | ⚠️ 必须显式传 `llm`，否则 QueryFusionRetriever 会去找 OpenAI key 并报错 |
| `reranker.py` | bge-reranker-v2-m3 精排 | 单例 + 本地快照；GPU fp16 |
| `query_transform.py` | Step-back 改写 | 默认关闭（多一次 LLM + 一次检索，实测收益不明显） |

### 生成链路（`app/core/generation/`）

| 文件 | 职责 | 关键点 |
|---|---|---|
| `prompt.py` ⭐ | SYSTEM_PROMPT 与上下文拼装 | `_clip_for_prompt()`：**含表格的切块放宽截断上限**——原来统一截到 1200 字符，正好把防火间距表的数值切掉，导致模型答"需查表" |
| `llm.py` | DeepSeek 调用 | 支持流式（SSE 未接前端）；`chat_direct()` 供出题/评估复用 |

### 评估（`app/core/evaluation/`）

| 文件 | 职责 | 关键点 |
|---|---|---|
| `retriever_eval.py` | 自建 HitRate / MRR / Recall / nDCG | 逐条明细写进结果，便于定位问题样本 |
| `ragas_eval.py` | RAGAS 三项指标 | ① `_patch_ragas_vertexai_import()` 绕过 ragas 0.4 与 langchain-community 0.4 的导入断裂；② 裁判 embedding 指向**本地快照**（否则卡在下载）；③ `_extract_item_scores()` 导出逐条得分 |

### 数据层

| 文件 | 职责 | 关键点 |
|---|---|---|
| `db/session.py` | SQLAlchemy 引擎 | Neon pooler（PgBouncer）**不接受 `options` 启动参数**，代码按 `-pooler` 自动区分；本地库不强制 SSL |
| `db/vector_store.py` | pgvector 封装 | 同步/异步两个连接串都要显式给（否则拼出 `None:None@None`）；关联列名是 **`node_id`** 不是 `id`（写错会静默匹配 0 行、留下孤儿向量） |
| `db/models.py` | ORM：documents / chunks / chat_sessions / chat_messages / eval_records | `Chunk.hypothetical_questions` 存 HyPE |
| `utils/cache.py` | 语义缓存（LRU/Redis） | ⚠️ 计算向量**必须用 `embed_model_dep()` 单例**，不能用 `build_*()` |
| `core/memory/session_store.py` | 多轮会话记忆 | `add_turn()` 批量写，把 4 次往返压成 1 次 |

### 前端

| 文件 | 职责 |
|---|---|
| `app/page.js` | 外壳与 4 个 tab、toast、健康轮询（30s） |
| `components/ChatTab.js` | 问答主界面：流式占位、引用出处、耗时显示、"语义缓存命中"标记 |
| `components/DocsTab.js` | 资料库：上传（XHR 进度）、文档列表、查看切块、重建/删除 |
| `components/SettingsTab.js` | 设置：top_k、是否启用缓存/改写、资料范围、外观 |
| `components/SessionsTab.js` | 会话列表与历史 |
| `lib/api.js` | `API_BASE`、`api()`、`apiUpload()`、localStorage、用户 ID |

## 4. `.env` 开关一览（改行为基本都在这里）

| 变量 | 默认 | 作用 / 什么时候动 |
|---|---|---|
| `DATABASE_URL` | — | 线上 Neon（pooler）/ 本地 Postgres，改一行即可切换 |
| `DEEPSEEK_API_KEY` | — | LLM 与 HyPE、评估裁判都用它 |
| `EMBEDDING_DEVICE` | `auto` | `cuda` / `cpu`；有独显务必确认走 GPU |
| `EMBEDDING_BATCH_SIZE` | `16` | GPU 下会自动提到 64 |
| `CHUNK_STRATEGY` | `semantic` | 改 `token` 可跳过 embedding 直接切块（免模型，但切块质量下降） |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 512 / 64 | 仅在 `token` 策略下生效 |
| `ENABLE_HYPE` | `true` | 关掉可省每块一次 LLM 调用（需重新入库才生效） |
| `ENABLE_CHUNK_FILTER` | `true` | 是否丢弃封面/目次/前言/参考文献等低信息密度段落 |
| `MIN_TEXT_QUALITY` | `0.15` | 低于此分判为乱码/扫描件 → 转 OCR |
| `PROMPT_NODE_MAX_CHARS` | `1800` | 拼进提示词的单块上限；含表格的块放宽到 3500 |
| `RETRIEVE_TOP_K` / `RERANK_TOP_K` | 10 / 5 | 召回数与精排保留数 |
| `ENABLE_QUERY_TRANSFORM` | `false` | Step-back 改写（多一次 LLM + 一次检索） |
| `RETRIEVAL_USE_ASYNC` | `false` | 保持 false；置 true 会触发 `Event loop is closed` |
| `SESSION_BACKEND` | `postgres` | 会话记忆存储 |
| `ADMIN_TOKEN` | `change-me` | ⚠️ **你的 `.env` 里这一项还是占位文本，需改成随机串** |
| `DB_STATEMENT_TIMEOUT_MS` | `30000` | pooler 下不通过 `options` 下发 |

## 8. 已知限制与待办（诚实清单）

**指标层面**
1. **faithfulness 0.832 未达 0.90 红线**。根因已定位：提示词只强制"依据"段标引用，
   而"操作要点"段允许合理推断（实测该段与检索上下文重合度 62.2%，明显低于"依据"的 77.7%）。
   修复方向已写在 `docs/评估方案.md` §3。
2. **检索指标循环性虚高**：140 题由切块自动生成，题干与原文高度重叠；只有 3 份资料、527 块，
   `top_k=10` 相当于在 1.9% 范围内检索。HitRate/Recall 已饱和在 1.000，**不具备区分度**。
3. **题库偏事实型**（约 128/140），与策略建议的 4:3:2 有差距。

**工程层面**
4. **跨进程缓存不刷新**：`ingest_cli.py` 入库后，正在运行的后端进程里 BM25 语料与检索器缓存仍是旧的，
   **必须重启后端**（缓存失效目前只在同进程内生效）。
5. **技术图内容不识别**：图题/图例是文字可检索，图形本身不解析（无多模态模型），

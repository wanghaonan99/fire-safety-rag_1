# 评估方案（v2 · 三份资料版）

> 本文件是**评估策略**，不是执行结果。执行状态见文末「当前进度」。
> 资料版本：GB/T 38315—2019（导则）+ 消防法（法律）+ GB 51283—2020（技术标准）

---

## 一、为什么资料从 1 份变成 3 份后，评估策略必须改

原来只有一份《社会单位灭火和应急疏散预案编制及实施导则》。它是**"教你怎么编预案"的导则**，
大量条款是模板句（"说明…/简述…"），从它出的题有 13/64 条答案只能靠模型编造（见阶段 1 记录）。

加入两份性质完全不同的资料后，评估的含义变了：

| | GB/T 38315—2019 | 中华人民共和国消防法 | GB 51283—2020 |
|---|---|---|---|
| **性质** | 推荐性国家标准的**导则** | **法律**（全国人大） | 工程建设**技术标准**（含强制性条文） |
| **内容特征** | 流程、要求"写什么" | 责任主体、义务、罚则 | 具体数值：间距、耐火等级、面积、灭火器 |
| **信息密度** | 低（模板句多） | 中高 | 高（条款+数值） |
| **最适合出的题** | 编制流程类 | **责任/义务/罚则/程序类** | **数值/技术判据类**（事实型主力） |
| **出题价值** | 中（需严格筛选） | 高 | **最高** |

**结论：评估集的主力应该来自消防法与 GB 51283，导则只贡献少量流程类题。**
按文档分配配额，而不是"每份平均出题"。

## 二、入库前必须先做的两项预处理（新发现，**不做会污染评估**）

这两项必须在"出题"之前完成，否则评估集和检索结果都会被噪声误导。

### 2.1 低信息密度切块要过滤掉

探查发现 GB 51283 的**目次页（第 5-8 页）**文字层质量分只有 0.00~0.06 —— 不是乱码，而是
目次本身"章节标题 + 点线 + 页码"的低信息文本，被我的质量分误判为乱码。

- **对入库无害**（全文质量分 0.295 > 0.15，不会误触发 OCR）
- **但对检索有害**：这类切块（封面、目次、前言、参考文献、起草人名单）会被召回成噪声。
  实测在之前的检索结果里就出现过**封面块和相关文献块被召回**，占掉了 top-5 名额。

**要做的事**：入库前按规则识别并丢弃低信息密度切块：

| 类型 | 识别特征 |
|---|---|
| 目次/Contents | 大量 `....` 点线、行尾页码、"目 次"/"Contents" 标题 |
| 封面 | 极短、"发布"/"实施"日期、无正文句式 |
| 前言/起草人 | "本标准由…提出"、"主要起草人" |
| 参考文献 | "参考文献"标题 + 编号列表 |

**验收**：入库后统计"被过滤块数"，人工抽 5 块确认没误删正文。

### 2.2 全角数字要归一化

消防法 PDF 的文字层是**全角数字**：

```
（１９９８年４月２９日第九届全国人民代表大会常务委员会第二次会议通过…根据２０２１年４月２９日…）
```

用户提问一定用半角（"消防法第 28 条"）。后果：

- **BM25 精确匹配失效**（`２８` ≠ `28`）
- embedding 尚可勉强匹配，但混合检索的一半能力被浪费

**要做的事**：`clean_text()` 里加全角→半角归一化（数字、字母、常见标点），
并把"第Ｘ条"统一成"第X条"。这是低风险、高收益的改动，且不影响已有资料（导则里没有全角数字）。

### 2.3 双栏排版必须按栏提取（**已实测，影响最大**）

《中华人民共和国消防法》是**人大公报的双栏排版**，pdfplumber 默认按 y 坐标逐行输出，
会把左右两栏的句子**交错拼进同一行**：

```
位做好消防宣传教育工作。 第十一条 国务院住房和城乡建设主管部门
教育、人力资源行政主管部门和学校、有关 规定的特殊建设工程，建设单位应当将消防设计
```

这种文本入库后每个切块都是"半句话 + 另半句话"，语义完全破碎，检索与问答都会失效。
**必须在解析阶段按栏提取**（先左栏后右栏），并对跨栏的居中标题/修订日期做整体抽出，
否则标题会被中轴切成"中华人民共 / 和国消防法"。

**验收**：抽取后第一页应输出"完整标题 → 完整修订日期 → 目次 → 第一章 → 第一条…"。

## 三、评估集设计（三份资料版）

### 3.1 规模与配额

| 来源 | 目标条数 | 题型 |
|---|---|---|
| **GB 51283—2020** | **12~15 条** | 数值/判据类为主（防火间距、耐火等级、灭火器配置、控温控压） |
| **消防法** | **8~10 条** | 责任主体、义务、罚则、程序（谁负责、罚多少、多久） |
| **GB/T 38315—2019** | **5~8 条** | 编制流程、分级分类、演练要求 |
| **跨文档辨析** | **3~5 条** | "这事该看哪份资料"（见 3.3） |
| **负样本** | **3 条** | 三份资料都没有的（**单独文件**，见 3.4） |
| **合计** | **28~38 条** | — |

> 比单资料版（20~25 条）更多，因为现在的检索要在 3 份资料、数百个切块里选，
> 评估才有区分度（单资料时 HitRate 会虚高到 0.9+）。

### 3.2 每条的必备字段

```json
{"question": "…", "ground_truth": "…", "ground_truth_ids": ["<能回答该问题的 chunk_id>"]}
```

- `ground_truth` 必须能在原文**逐字**找到依据（数值尤其）
- `ground_truth_ids` 必须是**真正能回答该问题的切块**，不是"出题时抽样的那块"

### 3.3 新增题型：跨文档辨析（有 3 份资料才出得来）

这是本次评估**最有价值的新增项**。例：

| 问题 | 正确答案应指向 | 考察点 |
|---|---|---|
| "精细化工企业的灭火器该怎么配？" | GB 51283（行业技术标准） | 会不会串到通用导则 |
| "单位没按规定编制预案要负什么责任？" | 消防法（法律责任） | 能不能定位到法律而非导则 |
| "演练多久组织一次？" | GB/T 38315 | 三份资料都可能提到，要选对 |

**判定方式**：`ground_truth_ids` 只标注**正确那份资料**的切块——若检索召回了另外两份资料的相似条款，
就是**跨文档串味**，属于真实失败。这类题能直接暴露"按类别过滤"功能的必要性。

### 3.4 负样本必须单独放（重要）

⚠️ **不要混进 `retrieval_golden.jsonl`**。

原因：检索评估脚本对"没有正确切块"的题一律判为未命中，混进去会**白白拉低 HitRate/MRR**。
负样本是给**拒答正确率**用的端到端测试。

**已建 `data/eval/negative.jsonl`（7 条）**，每条带 `category` / `why` / `acceptable` 便于复核：

| 类别 | 问题 | 库里为什么答不出 |
|---|---|---|
| 引用未收录 | 厂房内疏散楼梯最小净宽度？ | 只有"应按 GB 50016 执行"的**引用**，无原文 |
| 引用未收录 | GB 50140 的灭火器配置基准？ | 只有"尚应符合 GB 50140 的有关规定" |
| 地方性法规 | 《上海市消防条例》的演练频次？ | 只提到上海 DGJ 08-2133 与"十二五"规划 |
| 其他标准内容 | 自动喷水灭火系统喷头多久更换？ | 三份资料零命中 |
| 其他标准内容 | 消防安全责任人每年培训学时？ | 零命中 |
| 统计与案例 | 2023 年全国火灾起数？ | 规范/法律条文不含统计数据 |
| 其他标准内容 | 电动自行车厂房内充电要求？ | 零命中 |

**筛选方法**（可复跑）：`python scripts/check_negative_candidates.py`
为每个候选问题列出"若能回答则必然出现的特征词"，在 540 块里做命中统计，全部为 0 才算合格。
对"命中但只是引用"的情况（如 GB 50140）用 `scripts/show_term_context.py` 看上下文再判定。

**实测结果：拒答正确率 7/7 = 100%**（门槛 ≥90%），复跑命令：

```powershell
python scripts/eval_abstention.py            # 默认读 data/eval/negative.jsonl
python scripts/eval_abstention.py --show-all # 打印完整答案
```

回答方式符合预期：「根据现有资料无法确定」+ 说明参考资料里**有什么** + 建议查阅具体规范。

> 顺带修掉一个提示词缺陷：原 SYSTEM_PROMPT 第 2 条写的是
> "建议查阅《**XXX**》原文"，模型偶尔会把占位符 `XXX` 原样输出到答案里（实测出现 1 次）。
> 已改为不提供可复制的占位符，并明确禁止输出 XXX、禁止编造规范名称。

## 四、指标与门槛

### 4.1 检索层

| 指标 | 含义 | 门槛 | 变化 |
|---|---|---|---|
| HitRate@K | 前 K 条里有没有正确答案 | ≥ 0.85 | 3 份资料后**会更低，这是正常的** |
| MRR@K | 第一条正确结果的排名倒数 | ≥ 0.70 | 主要看它判断 Rerank 效果 |
| Recall@K | 多标注时的覆盖率 | ≥ 0.75 | — |
| nDCG@K | 排序整体质量 | ≥ 0.70 | — |
| **噪声率（新增）** | 检索到的切块里，低信息密度块（目次/封面/前言）占比 | **≤ 5%** | 直接对应 2.1 的过滤是否生效 |

### 4.2 生成层（RAGAS）

| 指标 | 含义 | 门槛 |
|---|---|---|
| faithfulness | 是否完全由上下文支撑（防幻觉） | **≥ 0.90（红线）** |
| context_precision | 上下文信噪比 | ≥ 0.75 |
| context_recall | 答案所需信息覆盖度 | ≥ 0.75 |

### 4.3 端到端自建指标（RAGAS 测不到，必须自建）

| 指标 | 怎么算 | 门槛 | 变化 |
|---|---|---|---|
| 拒答正确率 | 负样本上是否明确说"资料中未找到" | ≥ 0.90 | 3 份资料后**更关键**（相似条款变多，更容易硬答） |
| 引用准确率 | 答案里的 `[n]` 是否真的对应 sources[n-1] 的原文 | ≥ 0.95 | — |
| 关键数值命中率 | 数值（防火间距、面积、期限、罚款额）与原文逐字一致 | ≥ 0.95 | **新增重点**：GB 51283/消防法 有大量数值 |
| **跨文档正确率（新增）** | 3.3 类问题是否指向了正确的那份资料 | ≥ 0.80 | 衡量"不串味" |

## 五、消融实验矩阵（在原 6 组基础上扩充）

| # | 实验 | 怎么改 | 关注指标 |
|---|---|---|---|
| 1 | 关闭 Rerank | `RERANK_PROVIDER=none` | MRR |

## 七、风险与注意

| 风险 | 说明 | 对策 |
|---|---|---|
| **目次/封面污染** | 探查已证实存在；此前检索结果里就召回过封面块 | 2.1 的过滤 + 噪声率指标 |

#### ⚠️ 如何正确解读这组数字（重要）

**1.000 的 HitRate 不能理解为"系统已经很好"**，它有三个系统性虚高来源：

1. **循环性**：这 140 题是**从那 527 个切块本身生成的**，题干与来源切块存在强词汇/语义重叠，
   检索它们本就应该很容易；
2. **语料规模小**：只有 3 份资料、527 块，top_k=10 相当于在 1.9% 的范围里找；
3. **题型偏事实型**（约 128/140）：事实型问题的答案词往往就是切块里的原词。

**这组基线的真正价值**是证明"链路没坏、排序接近最优"，而不是证明"能应对真实提问"。

#### 对后续消融实验的直接影响

- **HitRate / Recall 已经饱和在 1.000，无法再区分好坏** —— 消融时不要看它们涨跌；
- **只能用 MRR / nDCG 作为区分指标**，而它们只剩约 5% 的提升空间（0.949 → 1.0），
  因此**不要期待消融实验出现大差异**；差异若小于 0.01 应视为噪声；
- 想让消融有区分度，应当**补充难度更高的题目**：
  - 人工编写的**跨文档辨析题**（"演练频次要查哪份资料"）
  - **跨条款归纳题**（答案需要 2 个以上条款，单一正确切块不唯一）
  - 员工**口语化提问**（与规范原文措辞差异大，削弱词汇重叠）

评估记录已写入 `eval_records`（`run_name=baseline-v1`, `eval_type=retrieval`, 140 条），
后续消融可直接按 `run_name` 对比：

```powershell
python scripts/analyze_eval_result.py data/eval_baseline_result.json   # 分资料/排名分布/串味率
```

> ⚠️ 与检索基线一样存在**循环性虚高**：题目源自切块、标准答案也是从那块内容生成的，
> 所以 precision/recall 偏高。**faithfulness 受这个影响较小**（它只看"答案是否被上下文支撑"，
> 不看答案对不对），因此 0.832 这个数字更接近真实水平，值得重视。

#### faithfulness 为何不达标：已定位到具体来源

用**不需要额外 LLM 调用**的代理分析（`scripts/diagnose_faithfulness.py`）把答案按
「结论 / 依据 / 操作要点」拆开，分别计算与检索上下文的 2-gram 重合度：

| 答案段落 | 平均重合度 | 低于 30% 的条数 | 判断 |
|---|---|---|---|
| 结论 | 77.9% | 4 | 基本有据 |
| 依据 | 77.7% | 0 | 基本有据（且都标了 `[n]` 引用） |
| **操作要点** | **62.2%** | **8** | ⚠️ **推断性内容集中在这里** |

**根因**：SYSTEM_PROMPT 要求"结论 + 依据 + 操作要点"三段式，但**只强制"依据"标注引用**。
于是"操作要点"里出现大量基于常识的合理推断——
"应立即排查…""建议由…负责""应定期检查…"——这些在原文中并不存在，被 RAGAS 判为无据内容。

> 补充说明：代理分析还统计出"39.3% 的答案含上下文里没有的规范号"，但经核对**大部分是误报**——
> 模型看到的上下文带有 `《精细化工企业工程设计防火标准（GB 51283-2020）》` 这样的定位行（含文档标题），
> 而代理脚本只比对切块正文，于是把"引用文档标题"误算成外部知识注入。**真正可信的信号是上面的段落重合度差异**。

#### 拟采取的修复（待验证）

收紧 SYSTEM_PROMPT，让三段式**全部**受上下文约束：

1. 明确"操作要点同样只能来自参考资料，找不到依据就写'资料未给出具体操作要求'"；
2. 禁止"建议/应当立即/应由…负责"这类推断性表述，除非原文如此；
3. 操作要点也要逐条标 `[n]`。

**验证方式（成本仅 10 分钟）**：第 1 批 40 条的 pre-fix 指标已知（faith 0.7801），
改完提示词只重跑这 40 条即可直接对比，无需重跑全部 140 条。

### 1c 出题结果与两个必须人工处理的问题

出题接口已改成分层抽样（原来按插入顺序取前 N 个，三份资料共存时会**完全漏掉最后入库的 GB 51283**），
并按文档切块数比例分配名额，同时让 LLM 输出题型标签。

| 维度 | 结果 | 说明 |
|---|---|---|
| 总量 | 149 条（失败 1） | 3.5 分钟，约 ¥0.5 |
| 按资料 | GB51283 **99** · 消防法 **34** · 导则 **16** | 与策略配额方向一致 |
| 按题型 | 事实型 **132** · 归纳型 13 · 易混淆型 4 | ⚠️ 严重偏斜，见下 |
| 预筛 | **118 条无机械问题**，31 条需核对（A14/B9/C2/E8/T8） | |

**问题 1：题型偏斜（事实型 89%，策略要 40%）**
技术标准里绝大多数切块都是"单条款 + 数值"，LLM 自然全出事实型。
→ 人工校对时应**把相邻条款合并成归纳型**（如"罐区隔堤 + 防火堤要求"合为一问），
或补一轮专项出题（提示词限定"必须综合 2 个以上条款"）。

**问题 2：部分题目不自足（必须改写，否则检索评估无意义）**
实测出现"员工个人有**前款**第二项、第三项行为之一的，罚款金额是多少？"这类题目 ——
问题里的"前款"离开了原文就没有指代对象。
→ 评估题必须是**自足**的（不看原文也能听懂），这类要改写成"违反消防法规定、过失引起火灾的，罚款多少"。

### 预筛规则的调整（减少误报）

`A-来源太短` 原本只按字数（<80 字）判断，在技术标准上**误报 59 条**：
标准的定义条款天生就短，例如"消防产品是专门用于火灾预防、灭火救援和火灾防护、避难、逃生的产品。"（39 字），
完全可回答。已改为"**短且没有完整句子**"才标记，误报降到 14 条。
→ 人工校对时，带 A 标记的先看是否有句号，有句号的基本可留。


### 表格与技术图的处理能力（实测结论）

| 内容 | 能否识别 | 做法 |
